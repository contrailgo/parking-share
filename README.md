# 사내 주차장 공유 시스템

지정 주차면을 가진 내부 배정자가 자리를 비울 때, 대기자·외부 배정자가 신청해서
쓸 수 있게 해주는 사내 웹

## 현재 상태

**프론트엔드 프로토타입 단계.** 실제 DB는 아직 연결되지 않았고, 모든 상태(등록/신청/취소)는
브라우저 메모리에만 저장됨 (새로고침하면 초기화). 명단은 `lib/mockRoster.ts`에
하드코딩되어 있고, 실제 회사 명단 파일 기준으로 이미 채워져 있음.

## 확정된 설계

- **인증 없음**: 이름 입력 → 명단과 대조해서 내부/외부/대기자 판별. 등록/신청/취소 시
  4자리 숫자 비밀번호를 함께 받아서, 나중에 본인이 취소할 때 그 비밀번호로 본인 확인함
- **두 개의 주차장을 독립적으로 관리**:
  - **지하 1층 신관** — 내부 배정자 43명, 도면 배치 그대로 그리드로 재현
  - **로비 주차장** — 내부 배정자 19명 (실제 이름 대신 임시로 "1"~"19" 순번 사용 중)
- **자리 상태 4가지** (색상으로 구분):
  - 회색 — 평상시 (등록 안 됨)
  - 초록 — 빈자리로 등록됨 (신청 가능)
  - 파랑 — 외부 배정자가 신청함
  - 보라 — 대기자가 신청함 (최우선순위, 더 이상 뺏기지 않음)
- **우선순위**: 대기자가 외부 배정자보다 우선이라, 파랑(외부 배정자 신청됨) 자리는
  대기자가 대신 신청해서 가져올 수 있음 (보라로 바뀜). 단 이 "우선예약"은
  **신청 대상 날짜의 전날 16:00까지만** 가능하고, 그 이후엔 이미 파랑인 자리를
  더 이상 가져올 수 없음 (안내 토스트만 뜸). 빈자리(초록) 자체에 대한 신청은
  마감 시각과 무관하게 항상 가능
- **취소**: "등록/신청 취소" 모드를 켜고 초록/파랑/보라 자리를 클릭하면, 등록·신청 시
  입력했던 비밀번호로 본인 확인 후 취소 가능
  - 초록(빈자리 등록 상태)을 취소 → 등록 자체가 사라지고 회색으로 완전히 복귀
  - 파랑/보라(신청된 상태)를 취소 → 신청만 취소되고 초록(빈자리)으로 되돌아감 (등록은 유지)
- **UI**: 리스트가 아닌 주차장 평면도 클릭 방식, 상단 날짜 선택기 (기본값 오늘),
  자리 호버 시 신청자 이름 툴팁
- **구현 형태**: 웹 (Next.js App Router)
- **배포 예정**: Vercel
- **DB 예정**: Vercel Postgres (Neon) + Prisma ORM (스키마는 있으나 아직 미연동)

## 프로젝트 구조

```
app/
  page.tsx                          # 메인 페이지 - 두 주차장 상태 관리, 툴바, 카드 레이아웃 전체
  layout.tsx                        # Geist 폰트 설정
  globals.css                       # 라이트모드 고정, 숫자용 Geist Mono 클래스
  api/                              # 초기에 만든 stub 라우트, 현재 미사용
                                     # (등록/신청/취소가 전부 프론트엔드 상태로 처리되고 있어서
                                     #  이 라우트들은 호출되지 않음 - DB 연동 시 정리 또는 재사용 예정)
components/
  FloorPlan.tsx                     # 지하 1층 신관 평면도 (43자리)
  LobbyFloorPlan.tsx                # 로비 평면도 (19자리) - FloorPlan과 동일한 구조/로직
  VacancyRegisterButton.tsx         # "빈자리 등록" 버튼 + 모달 (이름/비밀번호/기간 입력)
  SpotClaimModal.tsx                # 자리 클릭 시 신청 모달 (이름/비밀번호 입력)
  CancelModal.tsx                   # 취소 모드에서 자리 클릭 시 비밀번호 확인 모달
lib/
  mockRoster.ts                     # 임시 명단 (신관 43 + 로비 19 + 외부 66 + 대기 4)
  deadline.ts                       # 대기자 우선예약 마감(전날 16:00) 계산 유틸
  prisma.ts                         # Prisma client 싱글톤 (DB 미연동 상태라 아직 안 쓰임)
prisma/
  schema.prisma                     # DB 스키마 초안 (Employee, ParkingSpot, Vacancy, Request)
public/
  logo.png                          # GE HealthCare 로고
```

## 로컬 개발 시작하기

1. 의존성 설치
   ```bash
   npm install
   ```
2. 개발 서버 실행
   ```bash
   npm run dev
   ```
3. `http://localhost:3000` 접속

DB가 아직 연결되어 있지 않아도 화면은 정상적으로 동작함 (명단은 `mockRoster.ts` 기준).
`.env`에 `DATABASE_URL`을 넣고 `npm run db:push`를 돌리는 건 DB 연동을 시작할 때만 필요함.

## 테스트용 명단 예시

- **신관 내부 배정자**: 43명 실제 이름
- **로비 내부 배정자**: "1" ~ "19" (임시 순번, 실제 이름 미반영)
- **외부 배정자**: 50명 + 아세아도 소속 16명
- **대기자**: 4명
